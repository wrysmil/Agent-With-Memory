语义其实更代表的是事实 ，情节记忆是代表的故事

孤立的事实回丢失构建上下文

## <font style="color:rgb(15, 17, 21);">为什么要情节记忆（Episode）？</font>
<font style="color:rgb(15, 17, 21);">打个比方</font>

<font style="color:rgb(15, 17, 21);">语义记忆告诉你的是"用户是谁"（事实）：</font>

+ <font style="color:rgb(15, 17, 21);">"用户叫张三"</font>
+ <font style="color:rgb(15, 17, 21);">"用户用 Windows 系统"</font>
+ <font style="color:rgb(15, 17, 21);">"用户喜欢简洁回复"</font>

<font style="color:rgb(15, 17, 21);">情节记忆告诉你的是"用户做过什么"（故事）——完整的上下文链：</font>

+ <font style="color:rgb(15, 17, 21);">"上周三，用户让我帮他分析一个 Python 项目"</font>
+ <font style="color:rgb(15, 17, 21);">"我帮他用 pytest 跑了测试，发现 3 个失败"</font>
+ <font style="color:rgb(15, 17, 21);">"他选择了修复第一个失败"</font>
+ <font style="color:rgb(15, 17, 21);">"然后我们成功跑通了全部测试"</font>

## <font style="color:rgb(15, 17, 21);">为什么需要记录"故事"而不是"结论"？</font>
<font style="color:rgb(15, 17, 21);">因为孤立的事实会丢失关键上下文：</font>

| <font style="color:rgb(15, 17, 21);">只有语义记忆</font> | <font style="color:rgb(15, 17, 21);">加上情节记忆</font> |
| --- | --- |
| <font style="color:rgb(15, 17, 21);">"用户想运行测试"</font> | <font style="color:rgb(15, 17, 21);">"用户在修复 bug 时习惯先跑单元测试"</font> |
| <font style="color:rgb(15, 17, 21);">"用 pytest"</font> | <font style="color:rgb(15, 17, 21);">"他之前发现 pytest 比 unittest 快"</font> |
| <font style="color:rgb(15, 17, 21);">"失败了"</font> | <font style="color:rgb(15, 17, 21);">"上次失败是因为缺少依赖，这次可能不同"</font> |


## <font style="color:rgb(15, 17, 21);">情节记忆的核心价值：</font>
+ <font style="color:rgb(15, 17, 21);">保留完整决策链 — 不是"他做了什么"，而是"他为什么这样做"</font>
+ <font style="color:rgb(15, 17, 21);">工具使用历史 — 用户之前用哪些工具？成功还是失败？</font>
+ <font style="color:rgb(15, 17, 21);">跨会话关联 — "用户上次做类似任务时遇到了 X 问题"</font>
+ <font style="color:rgb(15, 17, 21);">失败模式识别 — "他总是忘记装依赖"</font>

## <font style="color:rgb(15, 17, 21);">情节记忆的来源</font>
<font style="color:rgb(15, 17, 21);">情节记忆是在会话结束时自动创建的（见 types.py:441）：</font>

<font style="color:rgb(15, 17, 21);">python</font>

<font style="color:rgb(15, 17, 21);">source: str = "session_end"  # session_end / context_compress / daily_consolidation</font>

<font style="color:rgb(15, 17, 21);">包含：</font>

+ <font style="color:rgb(15, 17, 21);">goal — 会话目标</font>
+ <font style="color:rgb(15, 17, 21);">outcome — 成功/部分/失败</font>
+ <font style="color:rgb(15, 17, 21);">action_nodes — 工具调用链</font>
+ <font style="color:rgb(15, 17, 21);">entities — 涉及的文件/对象</font>
+ <font style="color:rgb(15, 17, 21);">tools_used — 使用过的工具</font>

# <font style="color:rgb(15, 17, 21);">工作记忆（Scratchpad）是什么？</font>
<font style="color:rgb(15, 17, 21);">类比：你的办公桌便签</font>

<font style="color:rgb(15, 17, 21);">就像你在办公桌上放几张便签：</font>

+ <font style="color:rgb(15, 17, 21);">当前正在做的事（current_focus）</font>
+ <font style="color:rgb(15, 17, 21);">正在进行中的项目（active_projects）</font>
+ <font style="color:rgb(15, 17, 21);">还没解决的问题（open_questions）</font>
+ <font style="color:rgb(15, 17, 21);">接下来要做什么（next_steps）</font>

## <font style="color:rgb(15, 17, 21);">它和语义记忆/情节记忆的区别</font>
| <font style="color:rgb(15, 17, 21);">工作记忆 (Scratchpad)</font> | <font style="color:rgb(15, 17, 21);">语义记忆 (Semantic)</font> | <font style="color:rgb(15, 17, 21);">情节记忆 (Episode)</font> | |
| --- | --- | --- | --- |
| <font style="color:rgb(15, 17, 21);">类比</font> | <font style="color:rgb(15, 17, 21);">办公桌便签</font> | <font style="color:rgb(15, 17, 21);">知识笔记本</font> | <font style="color:rgb(15, 17, 21);">日记</font> |
| <font style="color:rgb(15, 17, 21);">内容</font> | <font style="color:rgb(15, 17, 21);">当前任务状态</font> | <font style="color:rgb(15, 17, 21);">用户是谁的事实</font> | <font style="color:rgb(15, 17, 21);">过去发生的事</font> |
| <font style="color:rgb(15, 17, 21);">生命周期</font> | <font style="color:rgb(15, 17, 21);">跨会话保留，但经常更新</font> | <font style="color:rgb(15, 17, 21);">长期（TTL 控制）</font> | <font style="color:rgb(15, 17, 21);">半长期</font> |
| <font style="color:rgb(15, 17, 21);">更新频率</font> | <font style="color:rgb(15, 17, 21);">每次会话都可能变</font> | <font style="color:rgb(15, 17, 21);">很少变化</font> | <font style="color:rgb(15, 17, 21);">会话结束时固定</font> |

## <font style="color:rgb(15, 17, 21);">工作记忆的来源</font>
<font style="color:rgb(15, 17, 21);">Scratchpad 是** AI 自己维护的**：</font>

<font style="color:rgb(15, 17, 21);">python</font>

```plain
@dataclass
class Scratchpad:
    content: str = ""                    # 自由格式内容
    active_projects: list[str] = []      # 正在进行的项目
    current_focus: str = ""              # 当前焦点任务
    open_questions: list[str] = []       # 待解决的问题
    next_steps: list[str] = []          # 下一步计划
```

<font style="color:rgb(15, 17, 21);">写入时机：</font>

+ <font style="color:rgb(15, 17, 21);">AI 完成一个任务后 → 更新 active_projects</font>
+ <font style="color:rgb(15, 17, 21);">AI 发现问题没解决 → 加入 open_questions</font>
+ <font style="color:rgb(15, 17, 21);">AI 规划下一步 → 写入 next_steps</font>

## <font style="color:rgb(15, 17, 21);">工作记忆的用途</font>
<font style="color:rgb(15, 17, 21);">text</font>

```plain
用户: "继续上次的工作"
       ↓
AI 读取 Scratchpad
       ↓
current_focus: "优化数据库查询"
next_steps: ["添加索引", "测试性能"]
       ↓
AI 直接从上次停下的地方继续，而不是问"你上次在做什么？"
```

## 工作记忆流程图


意图识别（IntentAnalyzer）做 5 件事：

1. **路由分流（核心）**  
通过 intent 字段把消息分到 5 条不同的处理路径：闲聊跳过、问询只答、任务干活、追问精简、指令严格执行。这是整个系统的第一个分叉点。
2. **决策上下文加载策略**  
根据 prompt_depth + memory_scope + memory_keywords + tool_hints 四个字段，决定这次对话要带什么上下文：

**记忆：查多少、查哪段、查什么关键词**  
**工具：提前加载哪些工具 schema**  
**prompt：详简到哪一档**  
**3. 设置执行护栏**  
通过 risk_level 决定要不要走人工审批（删文件、push 代码等高危动作），通过 capability_scope 限定可调用的工具域（防止越权）。

4. **评估复杂度，决定是否进入规划模式  
****通过 complexity（5 个布尔位）+ todo_required，判断任务是否需要拆 Todo、是否需要进入 Plan 模式。多步/跨模块/模糊需求 → 强制规划。**
5. **写入工作记忆**  
把 task_definition 塞进 Scratchpad 的 current_focus，is_cross_session 决定要不要跨会话检索历史情节记忆。

## 意图分析 Prompt 模板
```python
# ============== Prompt 模板 ==============

INTENT_ANALYZER_SYSTEM = """
你是用户消息意图分析器。请分析用户消息，判断其意图并提取关键信息。

## 输出格式
请严格按以下 YAML 格式输出，不要包含任何其他内容：

```yaml
intent: chat|query|task|follow_up|command
task_type: <任务类型描述>
task_definition: <任务定义（用于更新 Scratchpad）>
tool_hints:
  - <工具名1>
  - <工具名2>
memory_keywords:
  - <关键词1>
  - <关键词2>
capability_scope:
  - files|web|browser|plugin|skill|mcp|im|desktop|org|code
prompt_depth: fast|minimal|standard|full
memory_scope: none|pinned_only|relevant|full
risk_level: none|low|medium|high
complexity:
  multi_file_change: true|false
  cross_module: true|false
  ambiguous_scope: true|false
  destructive_potential: true|false
  multi_step_required: true|false
todo_required: true|false
is_cross_session: true|false
```





## 判断规则
# 顶层字段
+ **intent**（`chat`/`query`/`task`/`follow_up`/`command`）  
用户消息的意图类型，是整个系统最关键的路由开关：
    - `CHAT`：闲聊，不更新 Scratchpad、不查记忆
    - `QUERY`：纯问询（"X 是什么"），更新 Scratchpad 但不一定要执行动作
    - `TASK`：需要动手执行的任务，会进入完整的工具调用流程
    - `FOLLOW_UP`：对上一轮的追问，记忆范围更窄
    - `COMMAND`：明确指令型，要求严格执行
+ **task_type**（如"代码调试 / 信息检索 / 文档撰写"）  
对任务做更细的分类，便于后续选择不同的 prompt 模板或工具组合。
+ **task_definition**（一句话任务定义）  
直接写入 Scratchpad 的 `current_focus` 字段，是工作记忆的"主线"。
+ **tool_hints**（工具名列表）  
意图分析阶段预判可能用到的工具（如 `["read_file", "web_search"]`），提前加载这些工具的 schema 到 prompt 中，避免后面边用边查。
+ **memory_keywords**（关键词列表）  
用于触发记忆检索——把关键词喂给多路召回引擎（语义 + 情节 + 近期 + 附件），决定要不要从长期记忆里捞东西出来。
+ **capability_scope**（`files`/`web`/`browser`/`plugin`/`skill`/`mcp`/`im`/`desktop`/`org`/`code`）  
能力域白名单，决定这次会话能调用哪些类型的工具/插件。例如 `code` 域开启才能用 IDE 类工具。

---

# 控制类字段
+ **prompt_depth**（`fast`/`minimal`/`standard`/`full`）  
控制 prompt 的详简程度，省 token：
    - `fast`：极简模式，只塞必要指令
    - `minimal`：基本上下文
    - `standard`：默认
    - `full`：带上全部工具/记忆/MCP
+ **memory_scope**（`none`/`pinned_only`/`relevant`/`full`）  
记忆召回范围，从最窄到最宽：
    - `none`：不查记忆（闲聊）
    - `pinned_only`：只查用户固定置顶的记忆
    - `relevant`：基于关键词的相关召回
    - `full`：相关 + 近期全部
+ **risk_level**（`none`/`low`/`medium`/`high`）  
操作风险等级，决定是否触发人工审批：
    - `none`/`low`：直接执行
    - `medium`：可能弹确认
    - `high`：必须审批（删除文件、推送代码等破坏性操作）

---

# 复杂度信号
+ **complexity**（5 个布尔位）  
复合信号，用来判断要不要进 Plan 模式 / 拉 Todo：
    - `multi_file_change`：是否要改多个文件
    - `cross_module`：是否跨模块
    - `ambiguous_scope`：需求是否模糊
    - `destructive_potential`：是否有破坏性（删/改/推送）
    - `multi_step_required`：是否需要多步执行  
任一为 `true` 时倾向进入规划流。

---

# 流程开关
+ **todo_required**（`true`/`false`）  
是否需要建 Todo 列表。当 `multi_step_required=true` 或复杂度较高时为 `true`，把任务拆成 Todo 喂给 `TodoWrite`。
+ **is_cross_session**（`true`/`false`）  
是否跨会话——决定上下文检索要不要越过当前 session，去查历史 session 的情节记忆。`true` 时扩大检索窗口。
