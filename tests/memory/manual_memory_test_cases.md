# 记忆功能手工测试说明

> 用途：给测试人员在 WebUI 里手动发消息，验证「系统记住用户说的内容」这个功能好不好使。
> 数据存在本机 `~/.nanobot/workspace/memory/state.db`

---

## 开测前必看（重要）

**先确认一件事**：当前版本的 WebUI 聊天可能**不会自动记录**你的对话内容——因为记忆中自动记录的开关在代码里暂时是关着的（不是 bug，是还没接上）。

怎么判断这次能不能测？
发一条：`我喜欢喝冰美式咖啡`

- 如果之后在「设置 → 记忆」里能看到这条 → 说明功能开着，下面所有用例都能测。
- 如果什么都看不到 → 说明这次环境没开自动记录，下面的用例**预期都会不通过，但不是功能坏了**，需要先把开关打开再测。

每次测之前可以清空旧数据，方便看结果：

```bash
sqlite3 ~/.nanobot/workspace/memory/state.db \
  "delete from memories; delete from episodes; delete from scratchpad;"
```

---

## 系统是怎么「记」的（先看 3 个地方）

WebUI 的「设置 → 记忆」页面有 3 个标签页：

| 标签 | 记的是什么 | 打个比方 |
|---|---|---|
| **语义记忆** | 你说过的事实、偏好、技能、错误、规则 | 记「小陈是前端工程师」「喜欢喝美式咖啡」 |
| **情节** | 你交办过的任务经过，一段一段 | 记「帮用户写过图片加水印的脚本」这个任务 |
| **工作记忆** | 你现在正在聊什么（当前焦点） | 记「用户最近在聊爬虫」 |

---

## 每类记忆：什么时候产生、你（用户）怎么做

### 语义记忆（事实、偏好、技能、规则）

| 时机 | 用户操作 | 会记到什么 |
|---|---|---|
| **聊完一段**（系统每轮对话结束后后台整理） | 正常发消息聊天，不需要额外操作 | 这一轮里谈到的事实/偏好 |
| **会话被删除**（系统在删除前抢救式记录） | 在 WebUI 左侧会话列表，右键/菜单删掉这个会话 | 该会话里的内容被整理成语义记忆 |
| **你用了「必须/每次/不要/记住」这类词** | 正常发消息，例如「我每天**必须**九点前起床」 | 记成一条「规则」类型的记忆 |

> 注：聊天中途的自动整理，取决于功能开关打开（见开测前必看）。会话删除的抢救式记录不依赖那个开关。

### 情节（交办的任务记录）

| 时机 | 用户操作 | 会记到什么 |
|---|---|---|
| **会话被删除**时 | 在左侧会话列表**删除该会话** | 这段对话的任务过程整理成一条「情节」 |
| **聊完一段**后（功能打开时） | 正常聊天 | 临时整理的情节 |

### 工作记忆（当前在聊什么）

| 时机 | 用户操作 | 会记到什么 |
|---|---|---|
| **每发一条有用的话**（不是寒暄） | 正常发消息 | 「当前焦点」变成这句话的内容 |
| **换话题了**（大概第 4 句开始） | 明显聊另一个话题 | 旧话题收进「归档」，「当前焦点」变新话题 |

## 正式用例

> 每个场景都会写明：**①怎么操作 → ②看完去哪个标签页看 → ③通过标准（含「什么时候该出现」）**

---

### 场景 1：新手报到（测：自我介绍会不会被记住）

**操作**：开一个新会话，逐条发送，每条等回复后再发下一条：

1. 你好呀
2. 我叫小陈
3. 我是一名前端工程师，平时主要写 React
4. 我比较喜欢极简风格的界面设计
5. 我目前在做的一个项目是内部的数据可视化平台

**去哪里看**：发完后去「设置 → 记忆 → 语义记忆」。

**通过标准**：
- ✅ 第 1 条（你好呀）**没有**被记录（打招呼不记）
- ✅ 第 2~5 条被记成语义记忆，能看到「小陈 / 前端工程师 / 极简风格 / 数据可视化」
- ✅ **时机确认**：语义记忆是在**每轮对话结束后的后台整理**中出现的（不用你点任何按钮）；如果发完 5 条后语义记忆还是空的，说明自动记录开关没开（见开测前必看），不是这几条消息的问题
- ✅ 工作记忆「当前焦点」变成最后一条的内容（这个**发完即更新**，不用等）

---

### 场景 2：聊偏好细节（测：细节会不会丢）

**操作**：同一会话继续发：

6. 我习惯早上八点起床，先喝一杯美式咖啡，不加糖
7. 午休我一般听 Lo-fi 音乐放松
8. 我不太喜欢吃辣，但重庆火锅除外
9. 我的代码习惯用 4 空格缩进，不用 tab

**去哪里看**：「设置 → 记忆 → 语义记忆」。

**通过标准**：
- ✅ 新增 3~4 条语义记忆
- ✅ 「美式咖啡」「Lo-fi」「重庆火锅除外」这些**细节没丢**（重点看第 8 条，后半句「重庆火锅除外」如果掉了，属于丢内容，算 bug）

---

### 场景 3：交办一个任务，中途改主意（测：任务记录和改主意）

**操作**：同一会话继续发：

10. 帮我写一个 Node.js 脚本，用来批量给图片加水印
11. 水印放在右下角，透明度设 40%
12. 那个水印，如果图片本身很暗，会不会看不清？
13. 我的意思是，遇到暗色图片，水印要不要换个位置？
14. 算了，还是统一右下角吧，保持一致更重要
15. 最后记得输出一份处理报告

**去哪里看**：发完后**删除这个会话**（左侧会话列表里右键/菜单删掉），再去「设置 → 记忆 → 情节」。

**通过标准**：
- ✅ **时机确认**：一条完整的情节，是在**会话被删除时**被整理并保存的（用户操作：删除该会话）。如果不删会话，情节可能不出现或很晚才出现——这是设计如此
- ✅ 情节里出现 1 条任务记录，内容大致是「做图片水印脚本，右下角，40% 透明度，输出报告」
- ✅ 关键：记录体现**最后的决定**（第 14 条统一右下角），不把中间改主意前的话当结论
- ✅ 第 12 条是追问（「那个水印…」），**不该**多记一条新任务

---

### 场景 4：废话连篇（测：没营养的话不会被记）

**操作**：接着发：

16. 行
17. ok
18. 哈哈
19. 👌
20. 那行吧

**去哪里看**：「设置 → 记忆 → 语义记忆 + 工作记忆」。

**通过标准**：
- ✅ 语义记忆**没有**新增任何条目
- ✅ 工作记忆「当前焦点」还是上一主题（没被这些废话覆盖）——工作记忆只认「有用的话」

---

### 场景 5：突然换话题（测：话题切换）

**操作**：开一个新会话，连发：

21. 帮我对比一下 TypeScript 和 Rust 在 Web 服务端的生态
22. 重点看看各自的包管理器
23. 把结论整理成表格发给我
24. 我周末准备去爬山，帮我查一下附近有什么适合新手的小山

**去哪里看**：「设置 → 记忆 → 工作记忆」。

**通过标准**：
- ✅ **时机确认**：工作记忆的「换话题」判断，是从**第 4 条**消息开始才检测的（前 3 条不够）。第 4 条（爬山）发出后，系统判定换话题
- ✅ 旧话题被收起来（归档/active_projects），「当前焦点」变成爬山
- ✅ 如果第 4 条发完后 **1 分钟内**再发一个明显换话题的消息，系统不重复处理——这是正常的防重机制，不是 bug

---

### 场景 6：现在能回忆起以前聊过的吗（测：检索/回想）

**操作**：接着上面的会话，问：

25. 我平时喝什么咖啡？
26. 我早上一般几点起床？
27. 我比较喜欢的界面风格是什么？

**去哪里看**：直接在回复里看（A 的回答里会带出记忆，或在「设置 → 记忆」看检索结果）。

**通过标准**：
- ✅ 回复里能看到「相关记忆」，内容沾边（问喝什么咖啡 → 翻出「美式咖啡」）
- ✅ 或 AI 主动说「我记得你说过……」

> ⚠️ 依赖功能开关：这一条需要自动检索打开（同开测前必看）。没开时是查不到的，不算这条用例的 bug。

---

### 场景 7：问没聊过的事（测：无关内容不乱翻旧账）

**操作**：接着问：

28. 帮我讲一个关于程序员的冷笑话
29. 黑洞是什么？给我科普一下

**通过标准**：
- ✅ 这类问题**不会**带出「相关记忆」——没关系的旧记忆不该硬塞进来

---

### 场景 8：聊完后结束会话（测：会话结束时的总结）

**操作**：开一个新会话，连发：

30. 我想整理一下我的重要日期
31. 我妈妈的生日是三月十二号
32. 我的结婚纪念日在每年六月

**去哪里看**：发完后**删除这个会话**（左侧会话列表删掉），再去「设置 → 记忆 → 情节 + 语义记忆」。

**通过标准**：
- ✅ **时机确认**：这段对话的总结，是在**会话被删除时**被触发的（用户操作：删除该会话）。如果你只是聊完不删会话，情节不会立刻出现
- ✅ 删除后，「情节」里出现一条记录，内容大概是「帮用户整理重要日期」
- ✅ 生日 / 纪念日这类时间点被记进语义记忆

**对照组**：再开一个新会话，只发一句「早上好」，然后删除 → 应该**什么都不记**（内容太少，系统认为不值得记，属正常保护机制）。

---

### 场景 9：聊一段正经需求（测：复杂对话的总结质量）

**操作**：开新会话，连发：

33. 帮我评审一下我设计的登录页，我把需求说一下
34. 背景是这个页面面向企业客户，B 端，量不大
35. 第一版只有邮箱+密码登录，不放第三方
36. 密码至少要 12 位，要求大小写数字都有
37. 对了，忘记密码的流程也要考虑
38. 不对，我改主意了，还是加上微信扫码登录吧
39. 为什么你觉得扫码登录在 B 端不适用？
40. 有道理，那就保持第一版（邮箱+密码），暂不加扫码
41. 就这样，谢谢你

**去哪里看**：发完删会话 → 「设置 → 记忆 → 情节 + 语义记忆」。

**通过标准**：
- ✅ **时机确认**：总结在**删除会话**时触发。结束后的「情节」以**最终决定**为准（邮箱+密码、12 位密码、暂不加扫码），不能把「加扫码」和「不加扫码」两版都记成事实
- ✅ 第 39 句是问为什么，正常询问
- ✅ 第 41 句「谢谢你」不新增记忆

## 觉的不对劲想直接看数据

WebUI 页面看不到的话，用这几条命令直接看数据库（要装 sqlite3）：

```bash
# 看语义记忆
sqlite3 ~/.nanobot/workspace/memory/state.db \
  "select type, substr(content,1,50) from memories order by created_at desc limit 20;"

# 看情节（任务记录）
sqlite3 ~/.nanobot/workspace/memory/state.db \
  "select summary from episodes order by ended_at desc limit 10;"

# 看工作记忆（当前焦点）
sqlite3 ~/.nanobot/workspace/memory/state.db \
  "select current_focus from scratchpad;"
```

## 遇到的问题怎么归类

| 现象 | 大概率原因 | 算不算 bug |
|---|---|---|
| 什么都没记（包括「我喜欢喝冰美式咖啡」这条测试语） | 自动记录开关没开 | 不算，是环境问题，先开开关 |
| 打招呼、懒回复被记了 | 意向判断把寒暄当成了有用信息 | 算 |
| 「重庆火锅除外」后半句丢了 | 记录时截断了细节 | 算，记录要完整 |
| 改主意后，两版方案都被记成事实 | 总结没跟上最终决定 | 算 |
| 聊得少（1~2 句）删除会话后没总结 | 内容不足不记（保护机制） | 不算 |
| 换话题后 1 分钟内重复触发 | 防重复机制 | 不算 |
| 画像、习惯分析这些细化功能看不到 | 相关功能目前没做完（占位） | 不算，暂未实现 |
| 不删会话时，情节一直不出现 | 「情节」主要靠删除会话触发（WebUI 没有「结束会话」按钮） | 不算，当前设计如此 |
